## 修改内容

- Applications 顶部 card 复用主要内容 card 的 `22px` padding，移动端复用 `16px` padding。
- Actions 中新增与 View 并列的 Delete，确认信息明确包含 Company Name 和 Job Title；成功后重新加载列表并显示简洁提示。
- 新增 `DELETE /api/applications/{id}`，移除同路径旧 archive handler 的路由绑定，并开放当前 feature retirement boundary 中的 DELETE 方法。
- Application Detail 的 Resume Snapshot 改为保留原换行和段落的可读文本展示。

## Delete API / database behavior

- DELETE 按当前用户和 Application UUID 定位记录并执行物理删除，不使用 soft delete、Trash 或 Restore。
- 只删除 `applications` 表中的目标记录及该记录内保存的 `resume_snapshot`。
- 来源 Analysis/History（`application_records`）、Resume 和 Resume Version 均保留，不修改其他记录。
- 本次不需要数据库 migration。

## Resume Snapshot 展示方案

- 检查确认 snapshot 来源为清洗后的 Resume `parsed_text`，数据库列类型为 plain-text `Text`；现有 Resume 页面没有可复用的正文 renderer 或 Markdown renderer。
- 采用最小 plain-text 展示容器，使用 `white-space: pre-wrap`、`overflow-wrap: anywhere`、`line-height: 1.7` 和 `78ch` 最大阅读宽度；不解析或修改 snapshot 内容。

## 前端变化

- Header padding 在 375px 宽度为 `16px`，在 768px 和 1440px 宽度为 `22px`；现有外层宽度与横向滚动规则保持不变。
- Delete 确认后进入单行删除中状态，调用 DELETE API，刷新 Applications 与 Resume 列表，并显示 `Application deleted successfully.`。
- Resume Snapshot 保留换行、空行和段落间距。
