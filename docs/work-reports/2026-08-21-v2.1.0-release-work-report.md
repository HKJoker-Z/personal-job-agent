# Personal Job Agent v2.1.0 Production Release Work Report

Date: 2026-08-21

Status: **RELEASED.** Production is running Version 2.1.0 at Alembic
`20260820_08` on the published immutable release images.

## Disk-capacity audit and resolution

The release initially stopped at the unchanged 6 GiB hard gate. The prior
measurement was 6,413,221,888 available bytes against a required
6,442,450,944 bytes. At the start of this continuation the available value was
6,399,389,696 bytes, 43,061,248 bytes below the same gate.

The root device is a 42,949,672,960-byte Virtio block device. GPT partition
`/dev/vda2` occupies 42,947,558,912 bytes and contains the ext4 root
filesystem; there is no usable unallocated tail space and no already-expanded
block device awaiting partition or filesystem growth. `df` reports a
42,156,257,280-byte root filesystem.

The read-only audit found `/var` at approximately 21.93 GB, led by
`/var/lib/containerd` at 17.08 GB and `/var/lib/docker` at 2.04 GB. Docker
reported 345 images using 13.32 GB, no actual dangling image candidates, three
small stopped containers, and 295 build-cache records using 4.841 GB. Of the
build cache, 2.527 GB was reported reclaimable. APT archives used 130,252,800
bytes. Journals used approximately 1.34 GB. Docker volumes, images needed by
Version 2.0.7 or Version 2.1.0, stopped containers, journals, temporary release
files, database files, backups, and persistent data were all retained.

Only two audited disposable-cache operations were performed:

- `docker builder prune --all --force`, after proving that no build was active;
- `apt-get clean` for downloaded package archives.

No Docker image, container, volume, journal, production log, backup, database,
Redis data, rollback snapshot, or release asset was deleted for capacity. The
build cache finished at one active 12.29 KB record with zero reclaimable bytes,
and APT archives finished empty. Available root space stabilized at
10,326,089,728 bytes after cleanup, an increase of 3,926,700,032 bytes. No
capacity gate, filesystem, partition, or volume setting was changed.

  healthy;

corrected atomically to the reviewed Version 2.1.0 values as part of cutover;
no secret value was printed or changed.

## Known issues

There is no known production-blocking issue from this release. The root disk
remains a fully allocated 40 GiB virtual disk, so future image, journal, and
backup growth should continue to be monitored even though the current margin
is comfortably above the release gate.

Three explicitly named isolated candidate/rehearsal Docker volumes totaling
123,223,262 bytes remain stopped and unattached because this operation was
instructed not to delete any Docker volume. They do not affect production and
were not used to satisfy the capacity gate. Their later removal requires a
separate, explicitly authorized volume-cleanup operation.
