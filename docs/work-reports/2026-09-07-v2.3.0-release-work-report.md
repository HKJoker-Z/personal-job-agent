```text

4242; 0 0 COMMENT - SCHEMA public pg_database_owner
```

Read-only rendering using `pg_restore --schema-only --no-owner --no-privileges`
shows `CREATE SCHEMA public;` without an ownership statement. The formal restore
command is `pg_restore --no-owner --no-privileges --exit-on-error
--single-transaction <connection arguments> <backup>/postgres.dump`.
The existing disposable-target preparation first performs guarded
`DROP SCHEMA public RESTRICT`. Consequently schema creation runs as the restore
login `postgres`, losing the special database-owner semantics.

A network-disabled, tmpfs-only disposable container using the exact server image
reproduced this: initial public owner `pg_database_owner`; after `DROP SCHEMA
public RESTRICT; CREATE SCHEMA public;`, owner `postgres`. That investigation
container was removed; no volume was involved.

Classification:

- A: not missing archive metadata; the TOC and manifest retain the correct owner.
- B/E: --no-owner intentionally suppresses ownership restoration; combined with
  schema removal/recreation this changes public ownership to the restore login.
- C: original PG16 initialization is correct; the subsequent restore preparation
  destroys that initial schema, and pg_restore recreates it with login ownership.
- D: not a server version/default difference; exact 16.9 image reproduced it.
- F: comparator is correct and remains unchanged.

`--allowed-owner-mapping pg_database_owner=postgres` and expected public owner

production restore summary is retained in `/tmp/pja-v220-direct-restore-validation.json`;
