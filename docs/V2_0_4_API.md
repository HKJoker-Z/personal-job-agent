# Version 2.0.4 API

Version 2.0.4 preserves existing authenticated routes and adds reliability
contracts to synchronous `POST /api/analyze`.

`X-Request-ID` accepts a safe bounded value or is generated by the Backend. The
effective ID is returned on responses and recorded in safe operational
metadata.

Analyze accepts an optional `Idempotency-Key` of 8–128 safe ASCII characters.
Keys are scoped to the authenticated user and Analyze operation. A completed
duplicate with the same canonical fingerprint returns the stored status/body
and `Idempotency-Replayed: true` without new provider or History work. Reusing
the key for changed input returns `409 IDEMPOTENCY_KEY_REUSED`; active duplicate
work returns a retryable in-progress error. Indeterminate provider outcomes
return `IDEMPOTENCY_OUTCOME_UNKNOWN` and are not retried automatically.

Analyze errors use:

```json
{
  "error_code": "STABLE_MACHINE_CODE",
  "message": "Safe human-readable message",
  "request_id": "correlation-id",
  "retryable": false
}
```

Authentication, trusted Origin, CSRF, ownership, and input validation run before
any replay disclosure. Raw keys, Resume/JD text, prompts, provider responses,
cookies, and secrets are not stored in the ledger.

The authenticated read-only `/architecture` frontend route documents the
implemented system. Monitoring endpoints preserve their response contract while
using bounded PostgreSQL aggregation.
